# Lite Recorder

在 Switch 上录制长视频，直接保存到 SD 卡。

Lite Recorder 由 Atmosphère 后台模块和 Tesla / Ultrahand 浮层组成。它读取系统提供的 H.264 视频流与 PCM 音频，在主机上写入 MKV 文件，无需连接电脑。

**当前版本：0.2.3 Beta。** 已在 Switch Lite 上验证基本录制流程；不同游戏、系统版本和长时间运行的兼容性仍需进一步测试。

## 功能

- **720p 视频**：接收 1280 × 720 的系统视频流，帧率由视频源决定，通常接近 30 fps，不保证恒定 30 fps。
- **长时间录制**：持续接收视频流，不受单次保存最近 30 秒的操作方式限制；实际录制时间受剩余空间和运行状态限制。
- **暂停与继续**：暂停后继续写入同一文件，暂停期间不计入录像时长。
- **视频源中断后恢复**：返回 HOME 等操作导致取流中断时，等待视频源恢复与关键帧，再接续当前文件。中断期间没有可补录的画面。
- **自动分卷**：单文件达到约 1 GiB 或 30 分钟后，在后续关键帧处分卷。视频参数发生变化时也会分卷。
- **菜单内查看状态**：显示状态、录像时长、录像总大小、音频数据、剩余空间、错误码、提示和保存位置，不在游戏画面常驻显示。
- **自动准备后台**：开机进入待机状态，点击“开始录制”才会保存录像。

项目不通过连续截图拼接视频，也不在主机上进行软件视频重编码。

## 使用条件

| 项目           | 要求 / 已验证范围                                                      |
| -------------- | ---------------------------------------------------------------------- |
| 系统环境       | 能正常运行自制后台模块的 Atmosphère 环境                               |
| 浮层环境       | 已安装并能正常使用 Tesla 或 Ultrahand                                  |
| 存储           | SD 卡有足够剩余空间；程序在剩余空间不高于 256 MiB 时拒绝开始或停止录制 |
| 已测试设备     | Switch Lite                                                            |
| 已测试系统组合 | 固件 23.0.1、Atmosphère 1.12.0                                         |
| 已测试游戏     | 《魔法使之夜》                                                         |

其他设备、固件和游戏尚不能视为已验证。请勿同时运行 SysDVR 或其他占用相同取流服务的录屏后台。

### 原本不支持录制的游戏

可能需要另行安装与系统固件匹配的 [dvr-patches](https://github.com/exelix11/dvr-patches)。它用于调整系统的录制限制，**不包含在本项目的安装文件中**，也不保证所有游戏或受限制场景都能录制。

根据该项目的发布说明选择补丁，按其说明安装后重启。系统升级后应重新检查补丁兼容性。使用 Lite Recorder 不需要另外安装 SysDVR。

## 安装与升级

仓库的 [output/SD](output/SD) 中提供安装文件。将其中的 `atmosphere` 和 `switch` 文件夹复制到 SD 卡根目录，合并同名文件夹，然后重启主机。

安装后应存在以下路径：

```text
SD 卡根目录/
├── atmosphere/contents/00FF4C5250524231/
│   ├── exefs.nsp
│   ├── toolbox.json
│   └── flags/boot2.flag
└── switch/.overlays/
    └── ovl-lite-probe.ovl
```

`exefs.nsp` 是后台模块文件，不需要用游戏安装工具安装。`ovl-lite-probe.ovl` 是菜单文件，保留该文件名即可。

升级时完整替换以上文件并重启，避免后台和菜单版本不一致。若安装包包含 `SD卡文件` 外层目录，应复制其内部文件夹，而不是把外层目录放进 SD 卡根目录。

## 使用方法

1. 进入游戏，通过已有的 Tesla / Ultrahand 快捷键打开浮层。
2. 选择 **Lite Recorder**，点击 **开始录制**。
3. 关闭浮层继续游玩；需要时重新打开菜单查看时长和大小。
4. 点击 **暂停录制** 后，可点击 **继续录制** 接续当前录像。
5. 结束时点击 **停止并保存**，确认保存完成后再关机或取出 SD 卡。

按钮根据当前状态变化：

| 状态                  | 可用操作             |
| --------------------- | -------------------- |
| 待机 / 已保存 / 错误  | 开始录制             |
| 正在录制 / 等待视频源 | 暂停录制、停止并保存 |
| 已暂停                | 继续录制、停止并保存 |

暂停和返回 HOME 不会单独触发分卷，但正常的大小、时长或视频参数变化条件仍可能触发分卷。

若提示缺少视频参数，请先保存游戏进度，再完全关闭并重新启动游戏。后台会尝试缓存游戏启动时输出的编码参数。

## 保存位置与格式

录像保存在：

```text
/recordings/lite-recorder/<本次录制目录>/
```

每次录制单独创建目录，包含 MKV 录像及用于诊断的 `summary.json`、`health.csv`、`segments.csv` 等文件。

| 项目 | 格式                               |
| ---- | ---------------------------------- |
| 容器 | MKV（Matroska）                    |
| 视频 | H.264，1280 × 720，沿用系统视频流  |
| 音频 | PCM，48 kHz、双声道、16 bit        |
| 播放 | 使用支持 H.264 + PCM 的 MKV 播放器 |

当前正在写入的文件以 `.mkv.part` 结尾；停止保存或完成分卷后才更名为 `.mkv`。**暂停不等于保存完成**。意外断电时，当前文件可能未完成收尾。

录像不会自动加入 Switch 系统相册。实际文件大小取决于视频内容；仅未压缩音频就约占 659 MiB / 小时，请为长时间录制预留空间。

## 后台资源占用

当前后台采用固定容量缓冲，录制时间增加不会导致媒体队列无限增长。

| 主要内存区域           | 容量         |
| ---------------------- | ------------ |
| 视频队列               | 2 MiB        |
| 音频队列               | 512 KiB      |
| 视频接收与写入临时缓冲 | 合计 1 MiB   |
| 后台堆                 | 384 KiB      |
| 主线程及两个读取线程栈 | 合计 192 KiB |

以上不是完整内存清单。0.2.3 对应构建产物的代码、数据和静态区合计约 **4.30 MiB**，加上单独配置的主线程栈约 **4.42 MiB**。两个读取线程栈和后台堆已包含在静态区中，不能重复累加。该值不包含系统管理开销、系统录制服务和 Tesla / Ultrahand 浮层，也不是实机进程内存测量结果。

**待机仍会取流。** 这样可以提前缓存部分游戏仅在启动时输出的视频参数；未开始录制时，媒体数据不会进入录像队列或写成录像文件。已分配的静态缓冲不会因待机而释放。

当前控制循环约每 10 毫秒检查一次命令文件，每秒更新状态文件及剩余空间。待机不等于零 CPU、零 I/O 或零耗电；尚未完成启用前后的帧率、功耗及续航对照测试。

## 验证状态与限制

- 0.2.0 已完成约 10 分 47 秒的实机录制验证，覆盖手动暂停、返回 HOME 和停止保存，产出文件通过解码与跳转检查。
- 0.2.1 对暂停后保持同一文件、取流中断、分卷等逻辑进行了电脑端媒体回放测试，20 个输出文件通过验证。分卷测试采用降低后的阈值。
- 0.2.2 / 0.2.3 已完成对应的界面逻辑、构建或安装包检查；不代表全部新版行为都已通过实机长期验证。
- 尚未完成多小时实机录制、真实 1 GiB / 30 分钟分卷边界及大量不同游戏的兼容性测试。

游戏没有输出可用视频流时，程序无法凭空生成画面。恢复通常需要等待关键帧，暂停及中断边界可能因此略过少量画面。SD 卡写入异常、空间不足或后台取流错误也可能中止录制。

## 实现概览

```text
系统录制服务 grc:d
    ↓
独立视频 / 音频读取线程
    ↓
固定容量队列
    ↓
录像控制：关键帧等待、暂停恢复、时间戳调整、分卷
    ↓
MKV 写入器 → SD 卡
```

浮层通过命令与状态文件控制后台，关闭浮层后录制继续。后台使用已有 H.264 码流，只进行必要的格式整理和封装；暂停恢复时调整输出时间戳，使录像时间轴接续。

主要源码：

| 文件                                         | 职责                                   |
| -------------------------------------------- | -------------------------------------- |
| [src/probe.cpp](src/probe.cpp)               | 后台入口、取流线程、命令处理与状态更新 |
| [src/packet_queue.hpp](src/packet_queue.hpp) | 固定容量媒体队列                       |
| [src/recorder.hpp](src/recorder.hpp)         | 录制状态、暂停恢复、时间轴和分卷       |
| [src/avc.hpp](src/avc.hpp)                   | H.264 参数解析                         |
| [src/mkv.hpp](src/mkv.hpp)                   | MKV 封装与索引                         |
| [src/overlay.cpp](src/overlay.cpp)           | 浮层菜单                               |
| [src/protocol.hpp](src/protocol.hpp)         | 后台与浮层通信格式                     |

## 从源码构建

当前构建脚本面向 **Windows PowerShell**，需要 devkitPro 的 devkitA64、libnx 和 Switch 工具。构建依赖版本及校验信息见 [dependencies.json](dependencies.json)。

在仓库根目录执行，将路径替换为实际 devkitPro 安装目录：

```powershell
.\build.ps1 -DevkitPro "C:\devkitPro"
node .\tools\check-package.mjs .
```

第二条命令需要 Node.js，用于检查构建产物的格式、模块 ID、权限配置及启动标记。生成的可部署文件位于 `stage/`，构建不会自动更新仓库中的 `output/SD/`。

主机端逻辑测试：

```powershell
.\tests\run-host-tests.cmd
```

该测试需要 MSVC C++ 和 Node.js。请在已配置 MSVC 环境的终端运行；脚本的自动初始化路径对应开发环境，其他安装位置可能需要调整。

媒体回放测试还需要原始采集测试数据、FFmpeg 和 FFprobe；入口为 [tests/run-recorder-tests.cmd](tests/run-recorder-tests.cmd)。测试数据不随仓库提供，普通用户录制不需要这些工具。

## 停用与卸载

完全关机后，删除 SD 卡上的以下项目：

```text
atmosphere/contents/00FF4C5250524231/
switch/.overlays/ovl-lite-probe.ovl
```

已有录像可保留。仅删除浮层不会停用开机后台；仅删除 `boot2.flag` 会取消开机启动，但打开录屏菜单仍可能启动后台。

## 反馈问题

提交问题时，请附上设备型号、系统与 Atmosphère 版本、浮层环境、游戏名称、复现步骤，以及菜单中的错误码。

如有对应录制目录，请优先提供 `summary.json` 和 `health.csv`。通常不需要上传完整录像；如需提供视频样本，请先确认其中没有不希望公开的内容。
